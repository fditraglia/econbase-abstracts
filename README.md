# Referee Recommender

[![Open in Spaces](https://huggingface.co/datasets/huggingface/badges/resolve/main/open-in-hf-spaces-md.svg)](https://huggingface.co/spaces/fditraglia/referee-recommender)

Suggests potential referees for an econometrics paper. Enter an arXiv ID from category `econ.EM` and get back a ranked list of authors whose recent work is closest to yours in embedding space.

## How it works

1. **Fetch** all `econ.EM` papers (primary + cross-listed) from arXiv.
2. **Embed** each title + abstract with [Qwen3-Embedding-8B](https://ollama.com/library/qwen3-embedding) (4096-dim) via a local Ollama server.
3. **Precompute** each paper's 100 nearest neighbors and their cosine similarities.
4. **Recommend**: look up the query paper's neighbors, then aggregate them by author to produce the referee ranking.

Step 3 is why the app is small. A query always names a paper already in the corpus, so the answers can be computed once rather than the vectors carried around: 4 MB of neighbor lists in place of 184 MB of embeddings, with identical output, since the interface never asks for more than 100.

## Run locally

The similarity table ships with the repo via Git LFS, so the app runs without Ollama, without the embeddings, and without a rebuild step.

**Prerequisites:** Python ≥ 3.12, [uv](https://docs.astral.sh/uv/), and [Git LFS](https://git-lfs.com/).

```bash
git lfs install                 # one-time per machine
git clone <this repo>
cd econbase-abstracts
uv sync                         # creates .venv and installs deps
uv run python app.py            # serves at http://localhost:5000
```

Open http://localhost:5000, paste an arXiv ID from `econ.EM` (e.g. `2606.12324`), and you'll get a ranked list of suggested referees.

Startup reads about 8 MB and takes a second or two. The app is ready once the terminal shows `Loaded N papers, top-100 neighbors each` followed by the date the corpus runs through.

## Updating the corpus

**Additional prerequisites:** [Ollama](https://ollama.com/) running locally, and the frozen embedding model.

```bash
ollama pull qwen3-embedding
ollama cp qwen3-embedding:latest qwen3-embedding-econbase:v1
uv run refresh_embeddings.py --dry-run   # what has changed since the last run
uv run refresh_embeddings.py             # embed, rebuild the table, publish
```

The refresh is incremental and safe to re-run: it asks arXiv what has changed, sorted by last-updated so revisions are visible as well as new papers, and embeds only those whose text actually moved. Building the whole corpus from nothing takes about half an hour on an M4 Max; a weekly update takes seconds.

The model is pinned to a local copy on purpose. The `qwen3-embedding` tag moves, and vectors from two different builds are not comparable — cosine similarities across the boundary would be meaningless with nothing to show it. The refresh checks the model's digest before writing anything.

## Data

Two files ship with the app:

- `econ_em_papers.parquet` — `arxiv_id`, `base_id`, `version`, `authors`, `title_raw`, `abstract_raw`, `title`, `abstract`, `primary_category`, `categories`, `is_primary_econ_em`, `published`, `url`, `text_sha`
- `similarity_top100.parquet` — `arxiv_id`, `neighbor_ids`, `cosines`

Both raw and LaTeX-cleaned text are kept so cleaning errors can be audited. `is_primary_econ_em` distinguishes primary from cross-listed papers. `base_id` is the identifier without its version suffix: a revision turns `2405.06779v3` into `v4`, so anything joining across updates keys on `base_id`, and the app accepts either form.

The 4096-dimensional embeddings are not in the repository. They are regenerated by `refresh_embeddings.py` and needed only for analysis and for rebuilding the similarity table.

## Deployment

The app is deployed to Hugging Face Spaces (Docker SDK, free CPU tier). The `Dockerfile` runs gunicorn on port 7860 (HF requirement) using the slimmer `requirements.txt` (no embedding-time dependencies).

```bash
git push hf master:main
```

The `hf` remote points to `git@hf.co:spaces/fditraglia/referee-recommender`.

## Notes

- We benchmarked Ollama against `mlx-embeddings`; Ollama (llama.cpp + Metal) was ~1.5× faster on an M4 Max.
- Qwen3-Embedding documents are embedded as plain text (no prefix). Only search-time queries get the `Instruct: ...\nQuery: ...` wrapper.
